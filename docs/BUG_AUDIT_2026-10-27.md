## Existing limitations and follow-up checks

- **Active rooms are in memory.** A Node restart, crash, deployment, or multiple independent Node processes still ends/splits active games. SQLite persists the song catalog, not rooms. This patch prevents the identified crash but does not introduce room persistence or clustered hosting.
- **The seeded catalog contains silent demo songs.** These are for testing game flow. Real play needs an applied Spotify playlist or imported songs with working track URIs. Starting the game does not guarantee audio is ready; use the new controls to check audio before playing.
- **Real Spotify audio and your Cloudflare deployment were not exercised.** Browser tests mock Spotify. Test the signed-in host, Premium account/app access, device transfer, autoplay on your actual browser, and a phone on another network. Spotify documents the need for a direct user action on autoplay-restricted browsers: https://developer.spotify.com/documentation/web-playback-sdk/reference#spotifyplayeractivateelement
- **A refreshed phone keeps its player only if browser storage survives.** A private browsing window, cleared storage, different browser, or another device has no reconnect token. Active-game late joining is still intentionally rejected.
- **Abandoned lobby entries remain until reused/reconnected.** There is no player-removal control; the room still has a 12-player limit. Create a fresh room when changing the group substantially. Offline turn recovery prevents these entries from trapping an already-running game.
- **Song years still require review.** Spotify supplies album release dates, which may refer to a reissue. MusicBrainz checks help but cannot establish every original release year. Existing manual corrections remain available.
- **Catalog edits during a game are live.** An admin can change a catalog song's year/title while a room is using it; imported playlist rooms use a private snapshot. Avoid catalog edits during a session until catalog snapshotting is implemented.
- **Startup documentation accepts any Node 20+, while Vite requires a sufficiently recent Node release.** Use a supported recent Node version. The Windows service/task scripts were read but not executed on Windows.

## Verification

Five newly added room tests were run against the original implementation and failed for the expected reasons: empty-deck skip charges a token, empty-deck Next throws, duplicate join fails, unrelated disconnect touches the room, and offline turn selection stalls.

Final clean-install results: **24 server tests, 3 real-socket integration tests, and 7 Chromium browser tests passed**. The production client/server build and TypeScript checks passed. Browser execution used a locally available Chromium binary via `CHROMIUM_EXECUTABLE_PATH`; actual Spotify audio was mocked.

Commands:

```sh
npm ci
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

`npm test` runs the rules/room/metadata tests and real Socket.IO integration tests. `npm run test:e2e` starts isolated local server/client processes and uses browser contexts for the display and separate phones. Browser fixtures mock Spotify and do not use an actual Spotify account. The test database lives under ignored `.test-data/`. An existing Chromium binary may be selected with `CHROMIUM_EXECUTABLE_PATH`.
